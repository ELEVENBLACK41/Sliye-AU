> 本文件记录 2.8-0 的基座盘点结果、职责边界和可复现验证基线，不承载业务实现。
> 日期：2026-09-04
> 对应执行计划：`AI地基完善与代码清理执行计划-2026-09-02.md`

## 1. 本轮范围

本轮完成 2.8-0：盘点 `packages/contracts/src/ai`、`apps/server/src/modules/ai`、`apps/web/src/features/ai` 和 `apps/web/src/app/api/ai` 的真实引用，冻结当前 Runtime 边界，并记录验证基线。

本轮不做：

- 不新增业务工具；
- 不迁移 `ToolLoopAgent`、`useChat`、`DefaultChatTransport` 或 UI Message Stream；
- 不删除占位文件、旧状态字段或数据库结构；
- 不执行 C0～C11；
- 不引入 RAG、Redis、Workflow、MCP、LangGraph 或独立向量库。

## 2. 当前主链与职责

```text
Browser AI Workspace
  -> Next.js /api/ai BFF 与 POST/GET 领域流
  -> Web Agent Runtime
  -> AI SDK streamText + tools + stopWhen
  -> NestJS 内部 Runtime 接口
  -> Tool Registry / Tool Invocation
  -> Decisions 业务域查询
  -> PostgreSQL
```

| 层级 | 当前职责 | 结论 |
| --- | --- | --- |
| `packages/contracts/src/ai` | Thread、Run、Event、ToolCall、来源、流协议和 Runtime 的共享契约 | 主链必需；继续保留 |
| `apps/web/src/features/ai/runtime` | 模型调用、工具循环、租约桥接、文本直出、事件推送和 Runtime 客户端 | 主链必需；当前不迁移 |
| `apps/web/src/features/ai/components` 与 `hooks` | AI 工作台、历史、工具轨迹、来源展示和 POST 流客户端状态 | 产品链路必需；继续保留 |
| `apps/web/src/app/api/ai` | 浏览器 BFF、Thread/Run 控制和 POST/GET 领域流入口 | 主链必需；继续保留 |

## 3. 当前工具边界

### 3.1 NestJS 中心注册表工具

当前 `AI_TOOL_DESCRIPTOR_REGISTRATIONS` 只注册：

- `findDecisionCandidates`：按当前用户可访问范围查找决策候选；
- `getDecisionContext`：读取通过前置发现唯一确认的决策上下文。

描述、输入输出契约、治理元数据和前置发现规则位于 `apps/server/src/modules/ai/tools/decision/`，执行器由 NestJS 负责实时鉴权和审计。

### 3.2 AI Gateway provider tool

`parallel_search` 在 `apps/web/src/features/ai/runtime/ai-agent-tools.server.ts` 中通过 `gateway.tools.parallelSearch()` 注入。它由 Gateway 执行，NestJS 只记录调用生命周期和网页来源摘要，因此不属于当前 NestJS 中心 descriptor 注册表。

### 3.3 明确不把占位文件当作已实现工具

`apps/web/src/features/ai/tools/decision/` 下的 `compare-proposals`、`draft-summary`、`get-decision-context`、`list-proposals`、`search-decision-events` 和 `search-discussion-messages` 目前只有注释占位，没有生产导入，也没有加入 NestJS 注册表。

## 5. 冻结结论

- AI SDK 负责模型调用、流式文本、工具 Schema/调用和多步循环。
- Web Runtime 负责当前执行桥接和产品流交互。
- NestJS 负责用户身份、实时权限、业务事实、来源可见性、审计和状态一致性。
- PostgreSQL 是业务事实与 AI 审计状态的权威存储。
- `AiEvent`、`AiStep`、租约/fencing、POST/GET 流、live sink、文本持久化队列和浏览器 reducer 当前均有主链引用，不作为 2.8-2 的直接删除对象。
- 当前已确认的清理候选只有占位工具文件、占位审批入口和后续通过引用检查确认的冗余代码；删除必须单项执行并定向验证。
