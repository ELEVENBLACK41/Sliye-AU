> 取代文档：`AI运行时官方能力收敛与渐进回退执行计划-2026-09-01.md`（仅作为历史方案保留）

## 1. 当前结论

当前采用的是“AI SDK Core + NextNest 业务运行时”的组合，而不是全量把运行时交给 AI SDK：

- AI SDK 负责模型调用、流式文本、工具 Schema/调用、多步 `streamText` Loop、停止条件、模型结果和 Gateway 适配。
- NextNest 负责 Thread/Run/Event 的业务状态、权限与来源可见性、幂等、租约/fencing、持久化、POST/GET 领域流、浏览器 reducer、队列和产品交互语义。
- 这套组合暂时不迁移 `ToolLoopAgent`、`useChat`、`DefaultChatTransport` 或 UI Message Stream，也不为了抽象一致性删除现有自建链路。
- 任何新增基础设施都必须先说明真实问题、收益、替代方案、接入成本和部署影响；第三阶段先不引入 Redis、Workflow、MCP、LangGraph 或独立向量库。

## 2. 本轮执行边界

本计划只负责 2.8“地基完善与代码清理”，不负责第三阶段新业务工具，也不负责 Runtime 迁移。

### 2.8-0：基座盘点与职责冻结

- 盘点 `packages/contracts/src/ai`、`apps/server/src/modules/ai`、`apps/web/src/features/ai` 及 `/api/ai` 路由的真实引用关系。
- 给每个运行时部件标记为：主链必需、业务安全必需、测试资产、兼容路径、占位、无引用候选。
- 冻结“AI SDK 负责模型层，NestJS 负责业务权威，Web Runtime 负责当前执行桥接”的边界。
- 记录当前直接相关的 contracts 类型检查、Web Runtime/协议测试和 Server AI 测试基线。

验收：引用清单、职责表、测试基线可以由命令复现；不改业务行为。

### 2.8-1：地基边界完善

- 只修复盘点中已经确认的边界缺口，例如重复契约、职责交叉、遗留占位导致的错误入口或测试准备不可靠。
- 已将活跃 Run 期间普通新消息的行为改为稳定拒绝，不再创建用户输入队列；同一幂等键仍可重放原提交结果。
- `AiRun.status = QUEUED` 仍保留为初始 Run 等待执行器领取的内部状态；`STEER` 调整方向和历史排队字段暂保留，后续单独评估是否继续。
- 继续保持权限、来源实时可见性、幂等、状态迁移、租约/fencing、Abort、事件顺序和错误归一化的一致性。
- 不新增通用抽象，不把现有业务状态重新包装成第二套 Agent/Tool/Stream 协议。

验收：对应的 contracts、Server AI 和 Web 定向测试通过；涉及跨 workspace 类型时同步检查调用方。

### 2.8-2：无关、无引用和过期代码清理

只清理同时满足以下条件的代码：

1. 没有生产代码、测试、脚本、文档、CI 或运行时动态引用；
2. 已确认不是兼容路径、数据迁移资产或安全门禁；
3. 删除后有直接替代物，或者其职责已经不存在；
4. 删除后能运行受影响范围的定向验证。

重点检查：空的 Hook、遗留 Mock 路由、重复协议适配、已废弃副本、只写不读的状态和过期文档入口。现有 Web 工具占位文件本轮明确保留，不作为 2.8 完成阻塞项；其他候选仍需逐项确认，不做批量猜删。

### 2.8-3：防御性代码减法

“防御性代码”不能按数量删除，先区分两类：

- 必须保留：权限复核、输入/schema 校验、事务与并发约束、幂等/fencing、Abort 传播、来源隐藏、流协议完整帧处理、状态终态保护、错误归一化和长度/预算上限。
- 可以评估简化：重复的空值兜底、永远不可达的分支、吞掉错误但不改变状态的 `catch`、已经由调用方或类型系统保证的重复判断，以及没有调用者的通用配置选项。

只有通过调用链、类型约束或回归测试证明“删掉不会改变安全、数据一致性和用户可见语义”后，才允许移除；不以减少代码行数作为完成标准。

### 2.8-4：清理后门禁

- 主链 Thread 新建、发送、流式输出、工具调用、停止、失败/重试、刷新恢复和权限失效语义没有回归。
- 无引用代码、占位入口和重复适配已得到明确处理，未留下新的死链。
- 当前 AI SDK Core 使用仍可验证，AI Gateway 模型解析和测试 Mock 不被清理误伤。
- 2.8 完成后才进入第三阶段 3.0/3.1；第三阶段继续沿用当前 `streamText` Loop，除非未来单独证明替换抽象能显著降低复杂度。

本轮收口结论：2.8 已完成。占位文件没有生产引用，继续保留为未来功能提示；TypeScript `EPERM` 属于验证环境遗留问题，记录为后续验证债务，不改变当前 Runtime 主链边界。

## 3. 明确不做

- 不执行 Gate C 的 C0～C11。
- 不把当前 Runtime 迁移成 `ToolLoopAgent`、`useChat`、`DefaultChatTransport` 或 UI Message Stream 主链。
- 不删除 `AiEvent`、`AiStep`、live sink、文本持久化队列、POST/GET 流、事件 reducer、租约或 fencing，除非后续有独立步骤、引用证据和替代方案。
- 不修改历史 Prisma migration，不做数据库删表或大范围数据迁移。
- 不新增第三阶段业务工具、RAG、Redis、Workflow、MCP、LangGraph、独立向量库或 admin 功能。

## 4. 每轮执行纪律

每轮只完成一个最小步骤。动手前说明目标、不做什么、主要文件和验证方式；完成后说明改动、原因、验证结果和下一步建议，然后停止等待检查。

代码清理优先使用“引用确认 → 单项删除/简化 → 定向测试 → diff 检查”的顺序。无法确认是否仍被动态路径、文档或部署脚本使用时，先保留并标记候选。

## 5. 推荐验证

- `rg` 引用检查：生产代码、测试、脚本、文档和 CI。
- `git diff --check`。
- `pnpm --filter @workspace/contracts check-types`。
- Web AI 相关 Node/协议/Runtime 定向测试和修改文件 ESLint。
- Server AI 定向测试；涉及共享类型或服务边界时补 AI 评测类型检查。
- 只有路由、workspace 配置或跨包构建受到影响时，才追加 Web/Server build；不机械执行全量 build。

## 6. 完成定义

2.8 不是“代码越少越好”，而是：AI 主链职责清楚、必要安全与一致性门禁保留、无关代码不再参与构建或运行、测试能证明清理没有回归，并且第三阶段可以在一个可理解的基座上继续推进。
