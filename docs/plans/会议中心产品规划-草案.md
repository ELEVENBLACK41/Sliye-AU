# 会议中心产品规划（草案）

> 文档状态：待评审，不写入最终 Obsidian 目录  
> 更新日期：2026-08-10  
> 目标读者：产品设计与后续开发实现  

## 1. 核心结论

会议中心定位为“当前用户的音视频协作枢纽”，同时承载两种强度不同的沟通：面向组织成员的快速通话，以及绑定项目、讨论分区或决策的正式项目会议。它负责聚合正在呼叫、进行中、待参加和历史记录；项目空间继续负责在具体业务上下文中发起正式会议。

两者的职责应保持清晰：

- 快速通话回答“我现在只想和某个人或几个人立即对齐一下”。
- 项目空间回答“为什么开、围绕哪个分区或决策开、邀请哪些上下文成员”。
- 会议中心回答“我要找谁快速沟通、今天要参加什么、现在能进入什么、过去开过什么”。
- 独立会议房间负责实时音视频、讨论、提案、投票和决议操作。
- 决策中心与决策回放负责沉淀跨会议形成的正式决策结果和过程证据。

不建议在“只能从群组里选人”和“完全无上下文的通用通讯录”之间二选一。推荐采用双链路：快速通话允许直接选择当前组织内可见的启用用户；正式项目会议继续受项目、分区和决策权限约束。两条链路共用音视频底座，但在权限、记录和正式业务操作上保持区别。

这里的“任意用户”不是互联网上任意账号，也不是跨组织任意呼叫，而是当前组织或租户内、状态正常且当前用户有权发现的成员。这样既覆盖测试与后端临时对齐的真实场景，也保留组织隔离、隐私和防骚扰边界。

## 2. 产品目标与边界

### 2.1 本期目标

1. 用户能在会议中心从组织成员中直接选择一人或多人发起快速语音/视频通话。
2. 用户能从项目空间的当前分区发起“立即会议”或“预约会议”。
3. 用户能在会议中心跨项目查看自己主持或受邀的会议，并查看最近通话。
4. 用户能快速识别呼叫中、进行中、即将开始、已结束、未接和已取消状态。
5. 用户能从会议中心进入会议房间、会前详情或会后记录。
6. 正式项目会议仍可关联零到多项决策，并在会议中沿用既有提案、投票、决议和时间线能力。

### 2.2 本期不做

- 不做跨组织、外部联系人和陌生人呼叫。
- 不把快速通话扩展成完整即时通信产品，不新增好友关系、私聊会话盒子和社交联系人体系。
- 不做决议后的任务分配、执行跟踪和结果验收。
- 不做复杂周期会议、会议室资源管理和第三方日历双向同步。
- 不在没有真实录制、转写或 AI 纪要接口时展示伪造的录像、转写和摘要。
- MVP 不做参会邀请的接受/拒绝流程；受邀即进入“我的日程”，后续再评估 RSVP。

注意：上一条只适用于预约的项目会议。快速通话必须有实时的接听、拒绝、忙线和超时未接状态，不能把被叫人直接拉入房间。

## 3. 入口关系

### 3.1 快速通话入口

会议中心头部提供高频主操作“快速通话”。用户点击后打开组织成员选择面板：

- 支持按姓名、部门搜索当前组织内可见的启用用户。
- 支持一对一和小范围多人通话；MVP 建议上限为 9 人，避免与正式会议能力重叠。
- 选择“语音通话”或“视频通话”只决定进入房间时的默认设备状态，不新增持久化会议模式。
- 项目、讨论分区和决策作为“关联上下文（可选）”折叠项，不阻塞呼叫；用户展开后按项目、分区、决策逐级选择。
- 发起后被叫端收到实时来电浮层，可接听、拒绝；超时后记为未接。
- 快速通话默认不要求标题、项目或群组，系统使用参与人生成可读标题。

适合测试与后端临时对齐、设计与产品快速确认等低准备成本沟通。快速通话默认只有参与人可见，不继承任何项目分区的可见范围，也不开放提案、投票和决议操作。

关联上下文遵循以下渐进规则：

- 从会议中心发起：默认不关联项目，保证“找人即呼叫”的效率。
- 从项目空间发起：自动带入当前项目和分区，但仍在通话前明确展示，让用户知道记录会归到哪里。
- 从某项决策发起：自动带入项目、分区和决策；参与人候选仍按该上下文权限裁剪。
- 呼叫开始后不因为缺少上下文限制音视频；后续可在通话中或结束后发起“归档到项目”的显式操作，但该能力放在第二阶段。
- 只有成功关联到用户有权访问的项目上下文后，才允许把通话内容接入提案、投票、决议和决策回放。

### 3.2 项目空间入口

在项目空间的“讨论”区域保留主入口，并将现有“在当前分区开会”升级为两个明确意图：

- **立即会议**：默认继承当前项目、当前分区、当前用户；选择参会人和关联决策后直接创建并开始会议。
- **预约会议**：除上述上下文外，必须填写计划时间，可选填写预计时长。

参会人候选范围继续遵守现有权限规则：公共分区只能选择项目成员，私有分区只能选择当前私有分区成员。关联决策只能选择项目级决策或当前分区的小组决策。

创建成功后的行为：

- 立即会议：直接进入独立会议房间。
- 预约会议：打开会议详情抽屉并提供“返回项目”和“查看会议中心”入口，不强制跳入尚未开始的房间。

### 3.3 会议中心入口

新版顶部导航“会议中心”指向 `/meetings`。页面同时提供：

- **快速通话**：直接选择组织成员，立即呼叫。
- **预约会议**：必须先选择项目与讨论分区，再复用正式项目会议创建能力，不能绕过项目上下文和权限裁剪。

### 3.4 会议房间与会后入口

- `/meetings` 是会议中心主页面，只负责日程、呼叫入口、进行中状态和历史聚合，不在主页面内直接承载完整音视频房间。
- `/meetings/[meetingId]` 是会议详情与会前/会后记录的次级路由。
- `/meetings/[meetingId]/room` 是实时音视频的独立全屏次级路由，复用现有 `(meeting)` 路由组，不继承会议中心顶部导航和复杂工作台外壳。
- 待开始会议先进入详情页，可由主持人开始会议；开始或接听后进入全屏房间。
- 已结束会议回到只读详情页，并可跳转关联决策和决策回放。
- 快速通话结束后进入“最近通话”，只展示参与人、实际时间、时长和接听结果；没有真实业务上下文时不伪造决策记录。

独立房间使用次级路由比把音视频放在会议中心主页面更合适：它能提供稳定深链、刷新恢复、独立权限校验和专注模式，同时会议中心仍可在用户返回后保持原来的日期与筛选状态。

实时房间根据上下文自适应右侧协作区：

- 已关联决策的项目会议：完整展示讨论、提案、投票和正式决议，所有操作继续调用既有决策接口并写入决策事件时间线。
- 只关联项目或分区、尚未关联决策：展示当前讨论和“选择/创建决策”入口，确认决策后再解锁提案、投票和决议。
- 未关联任何上下文的快速通话：默认只展示参与人和通话信息，同时提供“开启决策协作”入口；用户完成项目、分区和决策关联后，无需退出房间即可切换到完整决策工作台。

这套自适应规则能让正式会议在音视频过程中直接完成决策闭环，也避免测试与后端只对齐一句接口含义时，被迫面对一整套提案和投票表单。

## 4. 会议中心信息架构

### 4.1 页面头部

- 页面标题：会议中心。
- 说明：跨项目管理我的会议与决策讨论。
- 主操作：快速通话。
- 次操作：预约会议。
- 二级切换：我的日程、会议记录。
- 筛选：项目、会议状态、我的角色；筛选状态写入 URL 查询参数。

### 4.2 “我的日程”默认页

桌面端采用“主日程 + 右侧行动栏”的结构：

1. **日期导航**：今天、前后日期和本周日期条。
2. **当日日程时间轴**：按计划开始时间展示会议；会议卡显示标题、项目/分区、时间、参与人数和状态。
3. **正在进行**：右侧高优先级卡片，展示最需要当前用户处理的一场进行中会议，并提供“进入会议”。
4. **接下来**：展示最近三场待开始会议，提供查看详情。
5. **最近通话**：展示最近的已接、未接或拒绝通话，并提供再次呼叫。
6. **空档反馈**：当天无会议时展示真实空状态和“快速通话”“预约会议”入口。

移动端改为日期横向滑动 + 单列议程列表；正在进行会议吸顶显示，避免压缩成不可用的小型周历。

### 4.3 “会议记录”页

会议记录采用可搜索列表，不做无业务价值的数据大屏，并提供“全部、项目会议、快速通话”类型筛选。项目会议记录展示：

- 标题、项目、分区和会议状态。
- 计划时间、实际开始/结束时间。
- 当前用户角色、参与人数。
- 关联决策数量与决策状态摘要。
- 操作：查看会议记录、打开关联决策、进入过程回放。

默认按实际开始时间或创建时间倒序，并支持按项目、时间范围和状态筛选。

快速通话记录只展示实际参与者、语音/视频入口偏好、呼叫结果、开始时间和时长。它不展示项目、分区、关联决策等不存在的数据位。

### 4.4 会议详情抽屉

用户点击日程卡后打开详情抽屉，避免每次都离开聚合页。抽屉包含：

- 会议标题、说明、状态和时间。
- 所属项目与讨论分区。
- 主持人和参会成员。
- 关联决策列表。
- 状态对应操作：进入会议、开始会议、查看记录。

编辑会议、取消会议、调整参会人属于第二阶段能力；在接口完成前不放置失效按钮。

### 4.5 快速通话面板

快速通话使用 Sheet 或 Dialog，不跳转到单独的创建页面。面板按优先级分为：

1. 成员搜索与最近联系人。
2. 已选成员列表。
3. 语音通话、视频通话两个直接动作。
4. “关联上下文（可选）”折叠区；未展开时不占据主流程注意力。
5. 麦克风、摄像头设备预检；设备异常时在发起前给出明确处理状态。

关联项目后，面板用一行摘要展示“项目 / 分区 / 决策”，避免把快速通话表单膨胀成正式会议表单。

### 4.6 实时房间决策工作台

桌面端实时房间采用“音视频主舞台 + 右侧协作面板”布局。右侧面板使用现有业务语义切换：

1. **讨论**：复用当前会议来源的分区消息，并保留业务关联卡。
2. **提案**：展示关联决策的提案列表、状态和新建提案入口。
3. **投票**：展示当前投票轮次、候选提案、已投进度和提交动作。
4. **决议**：展示形成正式决议所需的来源提案、投票结果和决议创建入口。

音视频画面保持主视觉，决策面板可折叠；移动端使用底部 Sheet 在四个业务区域间切换，不把视频压缩成不可识别的小窗口。所有权限继续由后端判断，前端不能因为用户进入会议房间就默认授予提案、开票或形成决议权限。

## 5. 核心业务流程

### 5.1 快速通话

```text
会议中心或成员快捷菜单
  -> 点击“快速通话”
  -> 搜索并选择一名或多名组织成员
  -> 选择语音或视频作为默认入会状态
  -> 服务端校验组织边界、账号状态和呼叫权限
  -> 向被叫端发送实时来电事件
  -> 任一被叫人接听后创建或激活音视频房间
  -> 全部拒绝、忙线或超时则结束本次呼叫并记录结果
```

例如测试人员需要与后端简单确认接口含义时，直接搜索后端成员并发起语音通话即可，不需要先建群、切项目或创建决策。

### 5.2 从项目空间立即开会

```text
项目空间当前分区
  -> 点击“立即会议”
  -> 填写标题，选择参会人和关联决策
  -> 服务端校验项目、分区、成员和决策权限
  -> 创建会议并开始会议
  -> 写入邀请通知和各关联决策的会议开始事件
  -> 进入独立会议房间
```

“立即会议”只是创建命令语义，不重新引入已删除的持久化 `meetingMode` 字段。

### 5.3 从会议中心预约会议

```text
会议中心
  -> 点击“预约会议”
  -> 选择项目与讨论分区
  -> 填写标题、时间、预计时长
  -> 选择参会人和关联决策
  -> 创建待开始会议并通知受邀成员
  -> 返回会议中心，在对应日期显示会议
```

### 5.4 参加项目会议

```text
会议中心进行中卡片或通知
  -> 打开会议
  -> 服务端确认当前用户为受邀成员
  -> 签发短期 LiveKit 令牌
  -> 加入音视频房间
  -> 会议中继续使用讨论、提案、投票和决议能力
```

### 5.5 会议或通话结束

```text
主持人结束会议或全部实际参会人离开
  -> 关闭 LiveKit 房间并更新结束时间
  -> 项目会议写入关联决策的会议结束事件
  -> 会议中心从“进行中”移动到“会议记录”
  -> 快速通话进入最近通话，项目会议进入会后记录
  -> 只展示真实存在的参与、消息、决策和回放数据
```

## 6. 状态与权限

| 状态 | 主持人 | 受邀成员 | 分区内未受邀成员 |
| --- | --- | --- | --- |
| 待开始 | 查看、开始；后续可编辑/取消 | 查看会前信息 | 可按现有分区可见规则查看，但不可加入 |
| 进行中 | 加入、结束、正式业务操作 | 加入；按决策权限执行操作 | 可查看上下文，但不可获取 LiveKit 令牌 |
| 已结束 | 查看记录与关联决策 | 查看记录与关联决策 | 按分区可见规则只读查看 |
| 已取消 | 查看取消结果 | 查看取消结果 | 按分区可见规则只读查看 |

会议中心的“我的会议”只聚合当前用户是会议参与者的记录；项目空间的会议模块仍可展示当前分区或项目范围内可见的会议。这样可以避免会议中心被大量“看得见但与我无关”的会议淹没。

快速通话使用参与人私有可见性：只有呼叫参与者能看到记录和实时状态。被叫端必须主动接听，服务端不能因为用户在线就直接签发入会令牌。

| 快速通话状态 | 呼叫方 | 被叫方 |
| --- | --- | --- |
| 呼叫中 | 取消呼叫 | 接听、拒绝 |
| 进行中 | 加入、结束 | 加入、离开 |
| 未接/拒绝/忙线 | 查看结果、再次呼叫 | 查看结果、回拨 |
| 已结束 | 查看参与人、时间和时长 | 查看参与人、时间和时长 |

## 7. 现有能力评估与缺口

### 7.1 已有能力，可直接复用

- `MeetingSession`、参与人、会议与决策多对多关联、录制预留结构。
- 项目/分区可见性和参会人候选权限校验。
- 项目内创建会议、查询会议列表和查询会议详情。
- 主持人开始/结束会议，以及空房自动结束。
- LiveKit 加入令牌与房间关闭。
- 邀请通知、会议结束通知。
- 独立会议房间中的讨论、提案、投票和决议操作。
- 现有用户、部门与通知能力可作为快速通话的成员发现和提醒基础。

### 7.2 MVP 必补能力

1. 当前用户维度的跨项目会议与最近通话列表接口。
2. 按日期范围、状态、项目、上下文类型和我的角色筛选。
3. 快速通话的组织成员搜索、实时来电信令、接听、拒绝、忙线和超时未接状态。
4. 会议计划时长或计划结束时间；现有模型只有 `scheduledAt`，无法准确绘制时间轴卡片高度。
5. 新版 `/meetings` 页面及对应 loading、empty、error、success 状态。
6. 会议中心预约入口对项目、分区、成员与决策的级联加载。
7. “立即会议”命令链路，保证创建成功后可恢复地进入进行中状态。

### 7.3 第二阶段再补

- 待开始会议编辑、取消、参会人调整和联合主持人管理。
- 邀请接受/拒绝与 RSVP 状态。
- 将重要的快速通话在权限满足时关联或归档到项目、分区和决策过程。
- 会议前提醒策略。
- 真实录制、转写和 AI 纪要处理链路。
- 外部日历集成与周期会议。

## 8. 技术落位建议

### 8.1 前端

- 新版页面入口：`apps/web/src/app/(newroute)/meetings/page.tsx`。
- 会议详情入口：`apps/web/src/app/(meeting)/meetings/[meetingId]/page.tsx`。
- 实时房间入口：`apps/web/src/app/(meeting)/meetings/[meetingId]/room/page.tsx`；音视频与详情拆开后，详情页不再根据状态直接替换整个页面职责。
- 新版业务模块：`apps/web/src/features/meeting-center`。
- `meeting-center` 负责成员选择、来电交互、跨项目查询、筛选、日程和详情抽屉；现有实时房间继续由 `features/meetings` 承担。
- 首屏日程使用 Server Component 获取；日期切换、筛选、详情抽屉和创建面板使用 Client Component。
- 查询条件写入 URL，支持刷新、分享和浏览器返回。
- loading 使用与最终时间轴结构一致的骨架；error 支持局部重试；空状态不使用模拟统计值。
- 来电浮层作为 app 级能力挂在新版工作区外壳，确保用户切换页面时仍可接听或拒绝；实时状态通过现有 Socket.IO 能力传递，媒体仍由 LiveKit 承担。
- 进入房间前保存会议中心的 URL 查询状态，离开房间后返回原日期、类型和筛选条件。
- 复用 `@workspace/ui` 的 Button、Sheet、Tabs、Select、Popover、Calendar、Dialog 等组件，不在业务页面手写基础控件。
- 样式只使用现有主题变量和语义 token，不新增死色值。

### 8.2 contracts

建议新增并逐项写明注释：

- `MeetingContextType`：区分 `DIRECT` 快速通话与 `PROJECT` 项目会议；它表达业务上下文，不表达语音或视频媒体模式。
- `MeetingCenterQuery`：日期范围、状态、项目、上下文类型、角色和游标。
- `MeetingCenterListItem`：补充可空项目上下文、当前用户角色、呼叫结果和时间轴展示字段。
- `MeetingCenterListResponse`：分组数据、分页游标，不提供伪造统计。
- 快速通话邀请与信令事件：来电、接听、拒绝、取消、忙线、超时。
- 创建会议的预计时长字段，建议使用 `scheduledDurationMinutes`，避免依赖客户端推算结束时间。

### 8.3 NestJS 与 Prisma

- 新增当前用户会议聚合查询，例如 `GET /meetings?from=&to=&status=&projectId=&role=&cursor=`。
- 查询条件必须包含当前用户的 `MeetingParticipant` 关系，避免仅凭分区可见性把无关会议放进“我的会议”。
- 补充项目标题到查询结果，减少前端逐项目请求。
- 不建议为快速通话复制一套 `CallSession`、参与人和 LiveKit 生命周期。建议复用 `MeetingSession`，将 `areaId` 调整为可空，并新增稳定的业务上下文类型 `DIRECT | PROJECT`。
- 快速通话的呼叫结果应由明确的邀请/参与状态记录，不能只用 `CANCELLED` 同时代表拒绝、未接和主叫取消；具体可通过参与邀请状态与终止原因表达。
- `DIRECT` 记录只能由参与者查询；`PROJECT` 继续使用项目与讨论分区权限。所有正式提案、投票和决议操作必须要求项目上下文。
- 如果确认采用预计时长，为 `MeetingSession` 新增可空字段并通过 Prisma 命令生成 migration。
- 后续编辑与取消分别使用显式接口，不复用开始/结束接口伪造状态流转。

## 9. 迭代计划

### Phase 0：产品与交互定稿

- 确认会议中心只展示“我主持/我受邀”的会议。
- 确认快速通话开放给当前组织内可见启用用户，而项目会议继续按分区裁剪参会人。
- 确认预约项目会议 MVP 不做 RSVP；快速通话必须接听或拒绝。
- 确认计划时长字段和移动端单列日程方案。
- 评审本计划与原型，锁定信息架构。

### Phase 1：查询闭环

- 新增 contracts、跨项目会议查询和 BFF。
- 完成 `/meetings` 日程页、会议记录页、筛选和详情抽屉。
- 接通现有会议房间与记录页。

### Phase 2：快速通话闭环

- 完成组织成员搜索、实时来电信令、接听、拒绝、忙线、超时和最近通话。
- 复用 LiveKit 房间和会议参与人生命周期，不复制媒体基础设施。
- 完成通话参与人私有可见性和呼叫权限检查。

### Phase 3：项目会议创建体验

- 抽取会议创建表单到新版会议中心职责下，项目空间与会议中心共享明确的创建能力，而不是复用旧页面 UI。
- 补齐立即会议和预约会议两条路径。
- 接通邀请通知、页面刷新和错误恢复。

### Phase 4：会前管理

- 增加编辑、取消、参会人调整和联合主持人。
- 根据真实需求决定是否加入 RSVP 与会议提醒。

### Phase 5：内容沉淀

- 在真实录制、转写和 AI 纪要链路完成后，再为历史记录增加录像、转写和纪要入口。
- 继续与决策事件时间线、会议图谱和过程回放建立关联。

## 10. MVP 验收标准

- 从公共或私有分区发起会议时，候选成员与关联决策范围正确。
- 快速通话可以搜索并呼叫当前组织内可见的启用用户，不要求先创建群组或选择项目。
- 被叫用户能接听、拒绝，忙线与超时有明确状态；未接听前不会被直接加入房间。
- 快速通话记录只有参与人可见，项目会议继续遵守分区权限。
- 会议中心只展示当前用户主持或受邀的跨项目会议。
- 日程按用户时区和日期正确归类，跨天、无计划时间和已取消状态有明确处理。
- 进行中会议能进入 LiveKit 房间，未受邀用户无法获取加入令牌。
- 会议结束后能从日程移入历史记录，关联决策和回放入口仍存在。
- loading、empty、error、success 四种状态完整。
- 桌面端无双重滚动，移动端不使用被压缩的桌面周历。
- 页面不展示接口未提供的虚构人数、未读数、录像、纪要或统计。

## 11. 需要评审确认的决策

1. 会议中心是否严格只展示“我主持/我受邀”，而不是所有当前分区可见会议？建议：是。
2. 快速通话是否开放给当前组织内可见的全部启用用户，而不是只允许当前群组成员？建议：是。
3. 预约会议是否要求填写预计时长？建议：提供默认 60 分钟并允许修改。
4. 预约项目会议是否暂不做 RSVP，受邀即进入日程？建议：是；快速通话仍必须实时接听。
5. 快速通话是否默认仅保存参与人、时间、时长和结果，不自动生成项目/决策记录？建议：是。
6. 快速通话前的项目关联是否保持可选，并在项目/决策入口发起时自动带入？建议：是。
7. 实时音视频是否使用 `/meetings/[meetingId]/room` 独立全屏次级路由？建议：是。
8. 已结束会议在真实录制和 AI 纪要完成前，是否只展示文字讨论、关联决策和回放入口？建议：是。
